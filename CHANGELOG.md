# Changelog

## v2.0.0 (2026-10-22)

First release of the fork [noengo/smbpasswd-api](https://github.com/noengo/smbpasswd-api),
based on [0x3333/smbpasswd-web](https://github.com/0x3333/smbpasswd-web) 1.1.0.

### Breaking changes

- Token links now use the URL fragment: `https://host/#token` (was `/?token`).
- Tokens are stored hashed with a creation time: tokens generated by 1.x are
  no longer accepted. Generate new links after upgrading.
- Tokens expire after `--token-ttl` hours (default 24).
- Usernames are validated (`[A-Za-z0-9_][A-Za-z0-9._-]{0,63}`).
- Requires a Unix system (uses `fcntl`); tested with Python 3.13 and 3.14.

### Security

- The new password is sent to `samba-tool` / `smbpasswd` on stdin, never on
  the command line (not visible in `ps`, `/proc` or the sudo log).
- Single-use tokens, stored as SHA-256 hashes in `res/tokens` (mode 0600),
  consumed atomically; restored if the password is rejected so the user can
  retry. A new token for a user revokes the previous one.
- Atomic writes of the tokens file, locked between `gen-token` and the server.
- `res/` created 0700, files 0600; files keep the owner of `res/` when root
  runs `gen-token`; the server refuses to start if it can't use `res/`.
- TLS handshake moved to the request thread with a 15 s socket timeout; limits
  on simultaneous connections in total (`--max-conn`, 256) and per client IP
  (`--max-conn-per-ip`, 8).
- Security headers: Content-Security-Policy, X-Frame-Options, nosniff,
  Referrer-Policy, Cache-Control: no-store; Python version hidden. HSTS is
  opt-in (`--hsts-max-age`).
- Server-side password validation (length, control characters).
- Front-end libraries served locally from `static/vendor/` (no CDN):
  jQuery 4.0.0, SweetAlert2 11.26.25, Bootstrap 4.6.2 CSS, Font Awesome 4.7.0.

### Deployment

- systemd unit runs as the unprivileged `sambaweb` user through
  `/usr/bin/python3`, with sudo-compatible hardening.
- `sudoers.example`: NOPASSWD rule limited to
  `samba-tool user setpassword <username>` (sudo >= 1.9.10).
- README: install steps (root-owned code, private `res/`), reverse proxy
  section with an nginx example.

### Other

- Python 3.12+ compatibility (`ssl.wrap_socket` removed), threaded server,
  POST to non-API paths and directory listing handled properly.
- The page lets the user retry after a password policy rejection.
